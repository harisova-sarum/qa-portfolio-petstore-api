# QA Portfolio: API-тестирование Swagger Petstore

Коллекция автоматизированных API-тестов в Postman для публичного демо-API [Swagger Petstore](https://petstore.swagger.io/v2) — классического учебного REST API с сущностями Pet, Store и User.

## Цель проекта

Показать практическое владение тестированием REST API: проверку статус-кодов, структуры и содержимого ответа, позитивные и негативные сценарии, работу с переменными коллекции (передача id между запросами).

## Объект тестирования

Base URL: `https://petstore.swagger.io/v2`

Покрытые сущности:
- **Pet** — создание, получение, обновление, удаление питомца; поиск по статусу
- **Store** — оформление заказа, получение инвентаря, обработка заказа по id
- **User** — регистрация, получение, авторизация, удаление пользователя

## Что внутри

- [`petstore_api_tests.postman_collection.json`](./petstore_api_tests.postman_collection.json) — Postman-коллекция с запросами и автоматическими проверками (`pm.test`)
- [`test-cases.md`](./test-cases.md) — тест-кейсы в текстовом виде (дублируют логику коллекции для читаемости без Postman)

## Покрытые сценарии

По каждой сущности — позитивные проверки (корректный запрос → ожидаемый код и структура ответа) и негативные (несуществующий id, некорректные данные, неверный пароль).

Каждый запрос сопровождается автоматическими проверками:
- Код ответа (200, 404 и т.д.)
- Соответствие полей ответа отправленным данным
- Время ответа (для ключевых GET-запросов)
- Передача id созданного объекта между запросами через переменные коллекции — сквозной сценарий «создать → получить → обновить → удалить → проверить, что удалено»

## Как запустить

1. Импортировать `petstore_api_tests.postman_collection.json` в Postman (File → Import)
2. Выполнить коллекцию целиком через Collection Runner — папки Pet, Store, User можно запускать последовательно
3. Проверить результаты во вкладке Test Results — все проверки должны проходить (кроме случаев, когда сам демо-API временно нестабилен, это публичный стенд без гарантий SLA)
